# Plan 1 — Staging pipeline (`build/stage.chromium.js`) [M0]

> Part 1 of the Sidebery → Chromium MV3 migration.
> Master plan: `docs/migrate-plan.md` — read §0, §0.1 and §1 before starting.
> Prerequisites: none (this is the first plan).

## Goal

Create the staging-copy mechanism that merges upstream `src/` with a Chromium overlay
directory `src.chromium/` into `.staging-chromium/src/`, which later plans will build from.

## Ground rules (apply to ALL plans in this series)

- **Never modify existing files under `src/` or existing `build/*.js|ts` files.** All
  Chromium code lives in NEW files: `src.chromium/`, `build/*.chromium.*`, `patches/`.
  The only allowed edits to existing files are *additive* changes to `package.json`
  (new scripts / dev-deps) and `.gitignore` (new entries).
- Target Chrome ≥ 150. No version checks, no compat fallbacks.
- The Firefox build must stay unaffected: `npm run build` and `npm test` must still pass
  after your work.
- **Commit after each completed TODO** with message format `chromium: <short summary>`.
  Do not create branches. Example: `chromium: add staging script skeleton`.

## Context you need

- The repo root is the project root (contains `src/`, `build/`, `package.json`).
- Overlay mechanism (decision #5 in `docs/migrate-plan.md` §0): a file at
  `src.chromium/<relative-path>` shadows `src/<relative-path>` in the staged tree; new
  paths simply add files. Patches in `patches/*.patch` are applied to the staging dir
  only, never to the working tree.
- Existing build scripts to study for style/conventions: `build/copy.js`, `build/utils.js`,
  `build/all.vite.js`. Reuse their helper patterns (they are plain Node ESM scripts,
  `"type": "module"`).

## TODOs

1. **Create directories + docs.**
   - `src.chromium/README.md`: short explanation of the overlay rules (shadowing by
     relative path, "add files, don't modify upstream", every overlay must keep the same
     export shape as the upstream file it shadows).
   - `patches/README.md`: patches are `git apply`-style diffs applied to
     `.staging-chromium/` at stage time; last-resort mechanism only.
   - Commit.

2. **Write `build/stage.chromium.js`** (new file, Node ESM). Behavior:
   - Recursively copy `src/` → `.staging-chromium/src/`. Make it mtime-aware: skip copying
     a file if the destination exists and has an mtime >= source (fast re-runs for dev).
   - Overlay-copy `src.chromium/` → `.staging-chromium/src/` (same relative paths
     overwrite; always copy overlay files last so they win). Exclude `README.md`.
   - Apply every `patches/*.patch` (sorted by name) with
     `git apply --directory=.staging-chromium` (spawn `git`; fail the script loudly on a
     patch failure). Skip cleanly when `patches/` has no `.patch` files.
   - Delete stale files: if a file exists in `.staging-chromium/src/` but in neither
     `src/` nor `src.chromium/`, remove it (keeps staging clean after renames).
   - `--dev` flag: after the initial stage, watch `src/` and `src.chromium/`
     (`fs.watch` recursive) and re-stage changed files; overlay files always win over
     upstream files with the same relative path.
   - Leave a clearly-marked placeholder function `checkManifestDrift()` (empty for now,
     implemented in Plan 2) called at the end of staging.
   - Commit.

3. **Wire into the repo (additive edits only).**
   - `package.json`: add script `"stage.chromium": "node build/stage.chromium.js"`.
   - `.gitignore`: add `.staging-chromium/` and `addon-chromium/`.
   - Commit.

4. **Verify.**
   - Run `npm run stage.chromium`. Confirm `.staging-chromium/src/` mirrors `src/`.
   - Create a throwaway test overlay file `src.chromium/services/_stage-test.ts`, re-run,
     confirm it appears in staging; delete it, re-run, confirm it disappears from staging.
     Remove the throwaway file before committing.
   - Run `npm test` and `npm run build` to confirm the Firefox pipeline is untouched.
   - Commit any fixes.

## Exit criteria

- `npm run stage.chromium` produces a merged `.staging-chromium/src/` tree.
- Overlay shadowing, stale-file cleanup, and (empty) patch application all work.
- Firefox `npm run build` and `npm test` still pass.
