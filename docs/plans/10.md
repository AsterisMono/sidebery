# Plan 10 — Remove Sync entirely [M2]

> Part 10 of the Sidebery → Chromium MV3 migration.
> Master plan: `docs/migrate-plan.md` — read §4.2 and decision #2 in §0.
> Prerequisites: Plans 1–8. (Plan 3 already excluded the `popup.sync` build entry.)

## Goal

Stub every sync service, hide all sync UI (settings section, sync popup, sidebar sync
panel), and make legacy configs containing a sync panel load cleanly. No Firefox Sync,
no Google Drive sync on Chromium.

## Ground rules

No upstream `src/` edits — overlays (identical export shapes) or `patches/`. Use
`IS_CHROMIUM` only in overlaid/patched code. **Commit after each completed TODO**
(`chromium: <summary>`). Firefox build/tests stay green.

## TODOs

1. **Service stubs.** Overlay these files (read each upstream file first; keep exact
   export shapes, no-op everything, never throw): `src/services/sync.bg.ts`,
   `sync.fg.ts`, `sync.bg.firefox.ts`, `sync.fg.firefox.ts`, `sync.firefox.ts`,
   `sync.bg.google.ts`, `sync.fg.google.ts`, `sync.google.ts`, `google.ts`,
   `google.drive.ts` (confirm the exact list with `ls src/services | grep -i 'sync\|google'`).
   IPC actions (`saveToSync`, `loadSync`, …) become inert: return empty results.
   Commit (one commit for the batch is fine).

2. **Build exclusion double-check.** Confirm `build/vite.chromium.ts` and
   `build/html.chromium.js` (Plan 3) exclude the `popup.sync` page and its html
   processing; remove any lingering references in the Chromium copy step. Commit if
   changes were needed.

3. **Hide UI.**
   - `settings.sync.vue` section + its nav entry in the setup page (patch or overlay,
     smallest wins).
   - Sidebar Sync panel: remove `"sync"` from available panel types in the panel-config
     UI (grep for how panel types are enumerated — likely `src/defaults/` or
     `popup.panel-config`); hide `panel.sync.vue` / `panel.sync.entry.vue` rendering
     paths.
   - Export/import config UI: strip sync-related fields on Chromium import (overlay the
     import normalization; see also TODO 4).
   - Commit per logical group.

4. **Legacy config tolerance — auto-remove sync panels.** When a loaded sidebar config
   contains a sync panel, auto-remove it at load and show a one-time notice
   (per master plan: prefer auto-remove over placeholder). Find where panel configs are
   normalized on load (grep `panel` normalization in `src/services/sidebar-config*.ts`
   or similar) and overlay/patch the normalization. Use the existing notifications
   service for the notice. Commit.

5. **Command cleanup.** `open_sync_popup` was dropped from the Chromium manifest
   (Plan 2). Verify the drift check's expected-dropped set includes it, and grep
   `open_sync_popup` handlers in bg/fg keybinding dispatch — ensure a missing command is
   harmless (no error paths). Commit if fixes needed.

6. **Verify.** Both builds green; Firefox tests pass. Grep the built
   `addon-chromium/` bundles for `googleapis\|oauth\|drive` remnants (should be none or
   dead-stub only). Commit.

## Exit criteria

- All sync services stubbed; sync UI unreachable; sync panels auto-removed from legacy
  configs with a notice; no sync/identity code in the Chromium bundles.
