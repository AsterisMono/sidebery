# Plan 4 — Browser shim core + entry wiring + types [M1]

> Part 4 of the Sidebery → Chromium MV3 migration.
> Master plan: `docs/migrate-plan.md` — read §3 (platform adapter layer) fully.
> Prerequisites: Plans 1–3 (staging + manifest + build pipeline).

## Goal

Create `src.chromium/platform/browser-shim.ts` — the module that makes upstream code's
`browser.*` calls work on Chromium — covering the *simple* adapters, plus the entry-point
wiring so every page loads the shim first, plus the TypeScript shim declarations.
(Complex adapters — `tabs.onUpdated` filters, sessions emulation, `scripting`, side
panel — come in Plans 5 and 8; leave clearly-marked stubs for them.)

## Ground rules

Never modify files under `src/`. All work goes in `src.chromium/` (overlay: a file at
`src.chromium/<path>` shadows `src/<path>` in the staged build). Overlays must keep the
exact export shape of the file they shadow. Chrome ≥ 150 only — all `chrome.*` APIs are
promise-based; no callback wrappers needed. **Commit after each completed TODO**
(`chromium: <summary>`). Firefox `npm run build` + `npm test` stay green.

## Context you need

- Upstream code calls a global `browser` (Firefox WebExtension global), typed by
  `src/types/web-ext.d.ts`. Chromium has no `browser` global — the shim assigns
  `globalThis.browser` delegating to `chrome`.
- Read `src/types/web-ext.d.ts` to learn the exact surface upstream expects.
- Each page has an entry `.ts` (find them: grep `input` entries in `build/vite.ts`; e.g.
  `src/sidebar/sidebar.ts`, `src/page.setup/...`, `src/bg/background.ts`, popup pages).
  Wiring pattern per §3: for each entry used by the Chromium build, add a 2-line overlay
  at `src.chromium/<same path>`:
  ```ts
  import 'src/platform/browser-shim'
  export * from './<entry-basename>.core'   // see TODO 2 for the exact pattern
  ```
  …but note the upstream entry file itself is shadowed by the overlay, so you cannot
  re-import it by the same path. Use this pattern instead: the overlay entry imports the
  shim and then does `import('src/...')`-free side-effect execution by *copying nothing*:
  the cleanest approach is a tiny staged-build trick — name the overlay exactly like the
  upstream entry and have it `import 'src/platform/browser-shim'` followed by
  `import 'src/<entry-dir>/<entry-name>.main'` **only if upstream splits entry/main**.
  Check how upstream entries are structured first; if an entry is monolithic, instead
  configure `build/vite.chromium.ts` to inject the shim as the first module of every
  entry (e.g. a small Vite plugin that prepends the import at transform time for entry
  files, or use additional `input` + `import` injection). Choose whichever mechanism is
  simplest and touches no upstream file; document the choice in `src.chromium/README.md`.
- The service worker also needs the shim first — coordinate with Plan 7 (which owns
  `src.chromium/bg/background.ts`); here just make the mechanism available.

## TODOs

1. **`src.chromium/types/chrome-shim.d.ts`** — declare the `chrome` global with the
   subset of APIs the shim uses (`chrome.tabs`, `windows`, `runtime`, `storage`
   (incl. `session`), `contextMenus`, `sidePanel`, `scripting`, `search`, `alarms`,
   `action`, `commands`, `sessions`, `bookmarks`, `history`, `downloads`, `permissions`,
   `omnibox`, `i18n`, `extension`, `notifications`). Hand-written minimal declarations
   are fine (do NOT add `@types/chrome` — its shapes conflict with upstream
   `web-ext.d.ts`). Make sure it is picked up when type-checking staged code (it lives in
   the staged tree; verify with `vue-tsc` against `.staging-chromium` later, in Plan 18 —
   for now just keep it self-consistent). Commit.

2. **`src.chromium/platform/browser-shim.ts`** — a side-effect module that builds a
   `browser` object delegating to `chrome` and assigns `globalThis.browser`. Include
   these adapters (each maps to a row of the §3 table in the master plan):
   - Pass-through namespaces: `tabs` (except adapters below), `windows`, `runtime`,
     `storage` (incl. `storage.managed`, `storage.session`), `bookmarks`, `history`,
     `downloads`, `permissions`, `sessions` (native part: `getRecentlyClosed`/`restore`),
     `commands` (only `getAll` + `onCommand`), `i18n`, `extension`, `notifications`,
     `omnibox`, `search` (adapter in Plan 5), `alarms`.
   - `browser.browserAction` → alias `chrome.action`.
   - `browser.menus` → `chrome.contextMenus`, wrapped: `create()` strips `icons` and
     `onclick` MUST throw a descriptive error if passed (forces Plan 15 rework — better
     loud than silently broken); `overrideContext` → no-op; `onHidden` → inert
     `{ addListener() {}, removeListener() {} }`.
   - `browser.tabs.moveInSuccession` → async no-op.
   - `browser.tabs.captureTab`, `browser.tabs.hide`, `browser.tabs.show` → leave
     `undefined` (upstream call sites feature-check).
   - `browser.tabs.warmup`, `browser.tabs.toggleReaderMode` → async no-ops if present in
     `web-ext.d.ts` usage (grep upstream for call sites; add no-ops only for APIs
     actually called).
   - `browser.theme` → `{ getCurrent: async () => ({}), onUpdated: inertEvent }`.
   - `browser.pageAction` → no-op stubs for the methods upstream calls (grep
     `pageAction.` under `src/`).
   - `browser.windows.update` → wrapper stripping `titlePreface` before delegating.
   - `browser.windows.create` → wrapper stripping `titlePreface` (and any other
     FF-only props found by grepping upstream `windows.create(` call sites).
   - `browser.commands.update` / `reset` → leave `undefined`.
   - `browser.runtime.getBrowserInfo` → resolve `{ name: 'Chromium', vendor: '',
     version: <parsed from navigator.userAgent 'Chrome/x.y'>, buildID: '' }`.
   - `browser.contextualIdentities`, `browser.proxy`, `browser.webRequest`,
     `browser.identity`, `browser.storage.sync` → leave `undefined`.
   - `browser.extension.inIncognitoContext` → native pass-through.
   - Placeholder exports/TODO comments for: `sidebarAction` (Plan 8),
     `tabs.onUpdated` filter emulation + `sessions.set/getTabValue/WindowValue` +
     `tabs.executeScript` + `search.search` (Plan 5). For now: `sidebarAction` methods
     as loud-`console.warn` no-ops; `tabs.onUpdated` plain pass-through;
     `sessions.setTabValue` etc. throwing descriptive "not yet shimmed" errors.
   - Commit.

3. **Entry wiring** — implement the chosen mechanism (see Context) so that every Chromium
   build entry evaluates `browser-shim` before any upstream module. Verify by building
   (`npm run build.chromium`) and inspecting the emitted `sidebar/sidebar.js` (or
   equivalent chunk) for the shim code running first. Commit.

4. **Smoke check.** `npm run build.chromium` succeeds. Grep the built output to confirm
   no top-level `browser is not defined` hazards remain in entries (all entries import
   the shim). Run `npm test` + `npm run build` (Firefox) — green. Commit fixes.

## Exit criteria

- `globalThis.browser` is installed in every Chromium entry before upstream code runs.
- Simple adapters from §3 implemented; complex ones stubbed loudly with TODO markers.
- Both builds compile; Firefox tests pass.
