# Plan 5 — Complex shim adapters: onUpdated filter, sessions, scripting, search [M1]

> Part 5 of the Sidebery → Chromium MV3 migration.
> Master plan: `docs/migrate-plan.md` — read §3 (adapter table), §5.3, §5.4.
> Prerequisites: Plan 4 (`src.chromium/platform/browser-shim.ts` exists with loud stubs
> for exactly the adapters implemented here).

## Goal

Replace the Plan-4 stubs in `browser-shim.ts` with real implementations for the four
non-trivial adapters: `tabs.onUpdated` listener filters, `sessions` tab/window values,
`tabs.executeScript` → `chrome.scripting`, and `search.search` → `chrome.search.query`.

## Ground rules

No upstream `src/` edits — all changes in `src.chromium/`. Chrome ≥ 150. **Commit after
each completed TODO** (`chromium: <summary>`). Firefox build/tests stay green.

## TODOs

1. **`tabs.onUpdated` filter emulation.**
   - Firefox supports `browser.tabs.onUpdated.addListener(fn, { properties: [...] , ...})`;
     Chrome does not (verified). Upstream call sites: `src/services/tabs.fg.handlers.ts`
     (~line 41) and `src/services/tabs.bg.ts` (~line 174) — read both to see the exact
     filter shapes used (`properties`, possibly `windowId`).
   - In the shim, wrap `onUpdated.addListener/removeListener/hasListener`: when a filter
     object is passed, register a wrapper that ignores events whose `changeInfo` contains
     none of the requested `properties` (and applies any `windowId`/`tabId` filters
     used). Keep an internal `Map<originalFn, wrapper>` so `removeListener` works.
   - Normalize `changeInfo`: Chrome never emits `hidden`, `attention`, `sharingState`,
     `splitViewId`; it does emit `groupId`, `frozen`. Filtering only — do not fabricate
     values.
   - Commit.

2. **`sessions.set/get/removeTabValue` + `set/get/removeWindowValue` emulation** (§5.3
   basis; hardening comes in Plan 13).
   - Back with `chrome.storage.session` (10 MB quota at ≥111, default access level
     TRUSTED_CONTEXTS covers all extension pages — no `setAccessLevel` call needed).
   - Key scheme: `tv:<tabId>:<key>` and `wv:<windowId>:<key>`. Values JSON-serializable
     as-is (storage handles that).
   - `getTabValue`/`getWindowValue` must resolve `undefined` (not throw) when absent —
     match Firefox behavior upstream relies on (check upstream call sites: grep
     `getTabValue\|getWindowValue` under `src/`).
   - Cleanup: in the shim module register `chrome.tabs.onRemoved` and
     `chrome.windows.onRemoved` listeners that remove all `tv:<id>:*` / `wv:<id>:*` keys
     (get all keys via `storage.session.get(null)` and filter by prefix). Registration
     must be top-level-safe for the SW context (listeners registered at module evaluation).
   - Commit.

3. **`tabs.executeScript` → `chrome.scripting.executeScript`.**
   - Map `browser.tabs.executeScript(tabId, details)` where `details` is
     `{ file?, code?, allFrames?, runAt?, frameId?, matchAboutBlank? }` to
     `chrome.scripting.executeScript({ target: { tabId, allFrames, frameIds }, files,
     injectImmediately })`:
     - `file` → `files: [normalized]`, where normalization strips leading `../` / `./`
       (Firefox call sites pass caller-relative `'../injections/x.js'`; `scripting`
       paths are extension-root-relative — verified gotcha). Result should look like
       `'injections/pause-media.js'`.
     - `runAt: 'document_start'` → `injectImmediately: true`.
     - `code:` → **throw a descriptive error** naming the call site remedy (`{func, args}`
       overlays happen in Plan 16). Upstream `code:` call sites: `tabs.fg.ts` ~line 1167
       (force-discard) and `tabs.fg.preview.ts` (dropped with previews in Plan 11).
     - Return shape: Firefox resolves an array of per-frame results; `scripting` resolves
       `InjectionResult[]` with `.result` — map to the array-of-results shape upstream
       expects (check what the 17 call sites do with the return value; most ignore it —
       grep `executeScript` under `src/`).
   - Commit.

4. **`search.search` → `chrome.search.query`.**
   - Map `{ query, tabId }` → `{ text, tabId }` and `{ query, disposition }` →
     `{ text, disposition }`. Verified constraint: `tabId` and `disposition` cannot be
     combined — assert (throw) if both are passed. Upstream's 3 call sites pass one or
     the other (grep `search.search` under `src/` to confirm).
   - Commit.

5. **Verify.** `npm run build.chromium` succeeds. Add focused unit tests if a Chromium
   test config exists (it arrives in Plan 18 — if absent, write the tests under
   `src.chromium/platform/__tests__/` in a way Plan 18 can pick up, using mocked `chrome`
   globals, and note they're not yet in CI). Firefox `npm test` green. Commit.
