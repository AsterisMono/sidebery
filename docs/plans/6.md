# Plan 6 — Platform env: profile id, `about:` URLs, bookmark root ids [M1]

> Part 6 of the Sidebery → Chromium MV3 migration.
> Master plan: `docs/migrate-plan.md` — read §3 "Platform constants" and §5.11.
> Prerequisites: Plans 1–4 (staging, manifest, build, shim core).

## Goal

Fix the platform-specific constants and URL handling: profile-id derivation,
`about:*` → `chrome://` URL mapping, `moz-extension://` scheme checks, and Chrome
bookmark root IDs.

## Ground rules

No upstream `src/` edits. Overlays in `src.chromium/` shadow same-path files in the
staged build and must preserve export shapes. For big, frequently-changing upstream files
prefer a `patches/*.patch` over a full-file overlay (patches apply to the staging dir —
see `patches/README.md`). **Commit after each completed TODO** (`chromium: <summary>`).
Firefox build/tests stay green.

## TODOs

1. **Profile id (`getProfileId`).**
   - Read `src/services/info.ts`: upstream slices `runtime.getURL('')` at `[16, 52]`
     (fits `moz-extension://<uuid>/`). On Chromium the prefix is `chrome-extension://`
     (19 chars) + 32-char id.
   - Overlay `src.chromium/services/info.ts` with a scheme-agnostic implementation
     (e.g. `new URL(runtime.getURL('')).hostname`), keeping every other export identical
     to upstream (copy the file, change only the needed function; the overlay-check tool
     from Plan 18 will flag upstream drift).
   - Commit.

2. **`platform/urls.ts` + `about:` URL mapping.**
   - Create `src.chromium/platform/urls.ts` exporting a translation table + helper:
     `about:newtab` → `chrome://newtab/`; `about:privatebrowsing` → `chrome://newtab/`;
     `about:blank` → unchanged. Also export helpers `isNewTabUrl(url)` etc. as needed by
     the call sites below.
   - Find the ~36 `about:` call sites: `grep -rn "about:" src/ --include='*.ts'`.
     Targeted overlays (per master plan): `src/services/tabs.fg.handlers.ts`,
     `src/services/tabs.fg.create.ts`, and the URL helpers in `src/utils.ts`. For each:
     decide overlay vs. patch by file size/churn — `utils.ts` and the two tabs files are
     large: **prefer patches** that swap the specific comparisons/constants for imports
     from `platform/urls.ts` (or the inline `chrome://` strings). Leave cosmetic-only
     `about:` occurrences (e.g. help text) alone.
   - Also fix `moz-extension://` string checks in `src/utils.ts` URL helpers: make them
     scheme-agnostic via a prefix computed from `runtime.getURL('')` (same patch).
     Upstream tests (`src/utils.test.ts`) must keep passing on the Firefox source —
     patches only affect the staged Chromium tree.
   - Commit (one commit per patched/overlaid file is fine).

3. **Bookmark root IDs.**
   - Upstream constants in `src/defaults.ts`: `root________`, `menu________`,
     `toolbar_____`, `unfiled_____`, `mobile______` (grep to confirm exact names/usages —
     ~3 files use them). Chrome: `'0'` root, `'1'` bookmarks bar, `'2'` other.
   - `defaults.ts` changes often upstream → **use a patch** (`patches/`), not a full-file
     overlay, that redefines just those constants: root→`'0'`, toolbar→`'1'`,
     unfiled/other→`'2'`, menu→`'2'` (no menu root in Chrome; verify how upstream uses
     the menu root and pick the least-broken mapping — document the choice in the patch
     header comment). `mobile______` has no Chrome equivalent — map to `'2'` as well and
     note it.
   - Commit.

4. **Verify.** `npm run stage.chromium` applies all patches cleanly;
   `npm run build.chromium` compiles; `npm test` (Firefox) green — especially
   `utils.test.ts`. Commit fixes.

## Exit criteria

- Staged Chromium tree has correct profile-id logic, `chrome://` new-tab URLs,
  scheme-agnostic extension-URL checks, and Chrome bookmark root ids.
- All patches apply cleanly at stage time; Firefox tree byte-identical.
