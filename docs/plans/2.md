# Plan 2 — MV3 manifest, pinned key, drift check [M0]

> Part 2 of the Sidebery → Chromium MV3 migration.
> Master plan: `docs/migrate-plan.md` — read §2 (Manifest V3) and §0 decisions #1/#4.
> Prerequisites: Plan 1 (staging pipeline exists).

## Goal

Hand-write the complete Chromium MV3 manifest at `src.chromium/manifest.json`, pin a
stable extension ID via `manifest.key`, and implement the manifest drift check inside
`build/stage.chromium.js`.

## Ground rules

Same as Plan 1: never modify `src/` files; only add new files (plus additive
`package.json`/`.gitignore` edits). Target Chrome ≥ 150. Firefox build must stay green.
**Commit after each completed TODO**, message format `chromium: <summary>`.

## Context you need

- Source of truth for feature parity: `src/manifest.json` (Firefox MV2). Read it fully.
- The manifest is written by hand, NOT generated. A drift check keeps it honest after
  upstream syncs.
- Full mapping table is in `docs/migrate-plan.md` §2. Key points:
  - `manifest_version: 3`.
  - `background: { service_worker: "bg/background.js", type: "module" }` (no HTML page).
  - `side_panel: { default_path: "sidebar/sidebar.html" }` + `sidePanel` permission
    (replaces `sidebar_action`).
  - `action` replaces `browser_action`; no `theme_icons`.
  - No `page_action` (proxy popup removed).
  - Icons: PNG paths `assets/logo-16.png`, `-32`, `-48`, `-128` (generated in Plan 3 —
    referencing them now is fine).
  - Permissions — keep: `activeTab`, `tabs`, `storage`, `unlimitedStorage`, `sessions`,
    `search`, `contextMenus`. Add: `sidePanel`, `scripting`, `alarms`. Remove:
    `contextualIdentities`, `cookies`, `menus`, `menus.overrideContext`, `theme`,
    `tabHide`, `proxy`, `webRequest`, `webRequestBlocking`, `identity`.
    `optional_permissions`: `bookmarks`, `history`, `downloads`, `clipboardRead`,
    `clipboardWrite`. `optional_host_permissions`: `["<all_urls>"]`.
  - No `browser_specific_settings`.
  - `options_ui: { page: ..., open_in_tab: true }` (copy page path from FF manifest).
  - `commands`: copy ALL commands from `src/manifest.json` EXCEPT
    `_execute_sidebar_action` and `open_sync_popup` (both dropped on Chromium). Add the
    reserved command `_execute_action` with suggested key `Ctrl+E`. Chrome rules
    (verified): at most **4** commands may carry `suggested_key`; every shortcut must
    include `Ctrl` or `Alt`; `Ctrl+Alt` combos are forbidden. Keep `suggested_key` only
    on the 4 most valuable (`_execute_action`, `new_tab_on_panel`, `next_panel`,
    `prev_panel`) and strip all other `suggested_key`s. Fix any key that violates the
    Chrome rules on those 4.
  - `omnibox.keyword: "="` — keep as-is for now (Plan 17 verifies it empirically;
    fallback is `"sb"`).
  - Do NOT add `web_accessible_resources` for `sidebery/group.html` / `url.html`.
  - `version`: same as `src/manifest.json`.

## TODOs

1. **Generate the key pair and pin the extension ID.**
   - Generate: `openssl genrsa -out chromium-dist.pem 2048`. **Do NOT commit the .pem** —
     add `chromium-dist.pem` to `.gitignore`.
   - Derive the manifest `key` value (base64 DER public key):
     `openssl rsa -in chromium-dist.pem -pubout -outform DER | openssl base64 -A`.
   - Derive the extension ID from it (first 16 bytes of SHA-256 of the DER pubkey, mapped
     to a–p) — a small throwaway Node one-liner is fine.
   - Write `docs/chromium-id.md` documenting: the pinned extension ID, the `key`
     derivation commands above, and that the private key lives outside the repo (state
     where maintainers should store it: their own secret storage).
   - Commit (key field can be added to the manifest in the next TODO).

2. **Write `src.chromium/manifest.json`** per the mapping above, including the `key`
   field. Validate it is syntactically valid JSON and structurally complete
   (`node -e "JSON.parse(...)"` or similar). Commit.

3. **Implement `checkManifestDrift()` in `build/stage.chromium.js`** (replacing the
   Plan-1 placeholder):
   - Parse `src/manifest.json` and `src.chromium/manifest.json`.
   - Fail loudly (non-zero exit, clear message) if `version` differs.
   - Fail if the command-name sets differ, after applying the expected delta: Chromium set
     == Firefox set − {`_execute_sidebar_action`, `open_sync_popup`} + {`_execute_action`}.
     Keep the dropped/added sets as named constants so future plans can extend them.
   - Commit.

4. **Verify.** Run `npm run stage.chromium` — drift check passes. Temporarily bump the
   version in `src.chromium/manifest.json` to confirm the check fails, then revert.
   Commit any fixes.

## Exit criteria

- `src.chromium/manifest.json` is a complete, valid MV3 manifest with a pinned `key`.
- `npm run stage.chromium` fails on version/commands drift and passes otherwise.
- `docs/chromium-id.md` documents the ID and key handling.
