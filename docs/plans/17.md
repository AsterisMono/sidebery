## TODOs

1. **Drag-and-drop mime types.**
   - Audit `src/utils.ts:getUrlFromDragEvent` and `src/services/drag-and-drop.fg.ts`:
     keep reading `text/x-moz-*` (harmless on Chrome), ensure `text/uri-list` and
     `text/plain` are BOTH written and read (per master plan this is mostly already
     done). Patch/overlay only demonstrable gaps. Commit.

2. **`MozFocusEvent.explicitOriginalTarget` + other Moz event props.**
   - Grep `explicitOriginalTarget` (and `MozFocusEvent`) under `src/` fg code; guard
     each usage for Chromium (optional chaining / fallback to `event.target`) via
     patch/overlay. Commit.

3. **Locales check (§5.7).**
   - The build's `handleLocales` emits `_locales/<lang>/messages.json` — Chrome
     compatible. Chrome rejects unknown/invalid locale codes as directory names: list
     the generated locale dirs in `addon-chromium/_locales/` and validate each against
     Chrome's supported-locale list (documented on developer.chrome.com; e.g. region
     variants must be like `en_US` with underscore). Exclude/rename invalid ones in
     `build/copy.chromium.js`. Commit.

4. **Omnibox keyword.**
   - `omnibox.keyword: "="`: Chrome docs state no charset restriction, but it must be
     tested empirically. Keep `=` in the manifest; add a prominent item to
     `docs/plans/notes-verify-in-chrome.md`: "if Chrome rejects the manifest or the
     keyword doesn't trigger, change to `sb` in `src.chromium/manifest.json`". Verify
     `src/services/omnibox.bg.ts` works with the shim (read it; it uses plain
     `browser.omnibox` events — should pass through). Commit.

5. **CSS `-moz-` audit (§5.11).**
   - Grep `-moz-` under `src/styles/` and page styles. `-moz-dialog` colors in
     `background.html` are gone with the bg page — ignore. For each remaining hit decide:
     harmless on Chrome (unknown property/value ignored, standard fallback already
     present) → leave; actually broken rendering → add standard fallback via overlay
     `.styl` files only. Document per-hit decisions in the commit message. Commit.

6. **Keybindings final check (§5.6).**
   - Confirm manifest commands (Plan 2) minus dropped ones are listed by
     `commands.getAll` in the read-only UI (Plan 12), and the 4 `suggested_key`s comply
     with Chrome rules. Cross-check the drift-check constants still match. Commit if
     fixes needed.

7. **Favicons sanity (§5.8).** Read `src/services/favicons.bg.ts`/`favicons.fg.ts`:
   data-URIs in storage, canvas work in fg pages — MV3-safe as-is. Confirm no bg-side
   canvas/DOM usage survived into the Chromium bundle (grep the built bg bundle for
   `document.`/`canvas`). No changes expected. Commit notes if fixes needed.

8. **Assemble the M4 manual test checklist.** Consolidate
   `docs/plans/notes-verify-in-chrome.md` into a structured checklist grouped by area
   (boot/panel, tabs tree ops, menus, keybindings, search/omnibox, DnD (in-panel,
   cross-window, from-page-to-panel, to-bookmarks), bookmarks, history, snapshots
   (create/restore), settings pages, unloaded tabs, group pages, locales/UI language).
   This becomes the release gate for M4/M5. Commit.

## Exit criteria

- DnD, locales, omnibox, CSS, and event-prop guards done; complete manual test
  checklist committed at `docs/plans/notes-verify-in-chrome.md`.
