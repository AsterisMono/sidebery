# Plan 7 — Service-worker background entry [M1]

> Part 7 of the Sidebery → Chromium MV3 migration.
> Master plan: `docs/migrate-plan.md` — read §5.2 (bg → MV3 service worker) and §5.9
> (color scheme in bg).
> Prerequisites: Plans 4–6 (shim + adapters + platform env).

## Goal

Make the background run as an MV3 service worker: overlay `bg/background.ts` to be
SW-safe (no DOM, no `localStorage`, no `matchMedia`), replace the localStorage-based
inter-page marker, and make bg-side color-scheme logic DOM-free. Milestone M1's exit
criterion (with Plan 8): the tabs panel renders and reacts to tab events.

## Ground rules

No upstream `src/` edits — overlays in `src.chromium/` (same-path shadowing, identical
export shapes) or `patches/`. Chrome ≥ 150. **Commit after each completed TODO**
(`chromium: <summary>`). Firefox build/tests stay green.

## Context you need

- Read `src/bg/background.ts` fully — it is the entry you're overlaying. Identify every
  DOM/`window`/`localStorage` usage.
- Known DOM-dependent pieces (per master plan):
  - `markLocalStorage()` does `localStorage.setItem('sdbr', '+')`, read by
    `src/services/ippc.page.ts` (~line 54) — an inter-page "addon is alive" marker.
  - `window.getSideberyState` debug hook.
  - Color scheme probing via `matchMedia` in `src/services/styles.bg.ts` →
    `src/services/styles.ts:getSystemColorScheme`.
- IPC init ordering: read `src/services/ipc.bg.ts` and how `main()` in `background.ts`
  gates message handling — messages can arrive before init completes on SW cold start.
